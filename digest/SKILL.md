# セッション棚卸し (digest)

セッション履歴から「同じ指示を何度もしている」「同じエラーで何度も詰まっている」を検出し、スキル/ルール/CLAUDE.md への外部化を提案する。ゴールは提案までであり、作成はユーザーが承認した候補のみ。

`disable-model-invocation: true` を設定しているため、`/digest` と明示的に呼び出したときだけ動く。

期間(省略可): $ARGUMENTS

## 手順

1. **機械集計を実行する** — `node scripts/claude-digest.mjs --since <期間> -o <一時ファイル>` を実行する。期間は `$ARGUMENTS` があればそれを、なければ `30d` を使う。セッション履歴は数百MBあるため、直接読まず必ずスクリプトを経由すること。
2. **レポートを読む** — 出力された Markdown を Read で読む。
3. **意味レベルで補完する** — スクリプトのクラスタリングは文字類似度(bigram Jaccard)なので、言い回しが違う同種の指示は別クラスタに割れている。代表例を読み、意味的に同じもの(例:「超簡潔にPR説明を」と「PRの説明欄は簡潔に」)を統合してから候補化する。1セッション内だけの反復(UI微調整の応酬など)は候補にしない。
4. **既存アセットと突き合わせる** — `~/.claude/skills/`、`~/.claude/CLAUDE.md`、カレントプロジェクトの `.claude/skills/`・`.claude/rules/`・`CLAUDE.md` を確認し、既に外部化済みのパターンを候補から除外する。既存スキルの使用回数が0なら「使われていない」事実も報告する。
5. **分類して提案する** — 残った候補を次の基準で分類し、根拠(回数・セッション数・プロジェクト)を添えて提示する。
   - **スキル** — 明示的に呼び出す定型手順(1つのワークフロー)
   - **ルール / CLAUDE.md** — 毎回言わなくても常時適用されるべき規約。複数プロジェクト共通ならグローバル、固有ならプロジェクト側
   - **プラグイン** — 複数プロジェクトに配布・同期したいスキル群
   - **エージェント** — 独立コンテキストで走らせたい調査・レビュー役
6. **承認された候補のみ作成する** — ユーザーが選んだものだけを作成する。勝手に作らない。

## 検出の調整

- 類似度の閾値: `scripts/claude-digest.mjs` の `bestScore >= 0.5`
- 除外する承認・相槌ワード: 同ファイル冒頭の `ACK_WORDS`
- 繰り返し判定の最低回数: `--min-count`(デフォルト3)
